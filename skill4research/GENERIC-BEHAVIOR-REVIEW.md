# 新版通用科研技能：独立 forward-review

2026-10-10。直接读取当前 overnight-research-loop/SKILL.md 及全部五个 references，并重新读取当前 paper-reproduction-team/SKILL.md 与两个 references。未沿用旧版审查作为当前证据；未修改 skills、未启动真实作业。以下为行为演练，不是实验结论或性能证明。

## 当前证据边界

情景没有给定研究领域、原始日志、效应量或实现验证产物。因此，可以判定 A/B/C 的名字不同不足以构成机制多样性，也可以指出把关遗漏历史；无法仅凭情景断言该领域机制普遍无效。反思者的“预测不成立”先作为需要定位证据的 challenge，核实实验辨别力、实现有效和条件可比后才成为有效反证。

## 具体行为演练

### 1. 四槽位先做真实轮转

协调者维护唯一全局状态；提案者只写 proposal、执行者只写分配实现与运行产物、把关者只写 gate-review、验证者只写 challenge/证据审查。提案者不批准自己，执行者不验收自己；同一争议的把关者与独立反思者不能由同一 agent 扮演。

当前协调者＋提案者＋执行者已占三个活跃槽，剩余一个先给独立验证者，不能同时再声称把关者也在运行。把关者若已有上下文但暂停/结束，可先发送消息存入邮箱；需要实际回复时须先让提案者提交当前草案并结束本轮，或让验证者保存证据结束本轮，再恢复把关者。`interrupt` 是中断当前 turn 的手段，不自动证明槽位释放或反馈被处理，必须看宿主真实状态。各轮最多三个子 agent 同时工作，保存交接后可恢复相同身份/上下文；无法恢复则新审查者读取原始审查记录并注明身份改变。

### 2. 先落盘，再主动送达

验证者建立 `CH-01`，至少包含历史 run、当前运行、候选 revision、原始结果定位、条件差异、被反驳的预测、把关遗漏、影响范围和解除条件。协调者将 A/B/C 归入同一 mechanism_signature；把依赖旧放行的候选设 `under-challenge`，旧 approval 标失效/待复核，先阻断相关新派发。

通知实际相关 agents；消息范例：

> CH-01，A/B/C rev1，关联 run-old 与 run-current：历史同机制结果未支持预测 P，当前放行未引用该证据。证据在 [原始路径/定位]。先停止同族新派发；运行处理待核当前成本与诊断价值。请回执 message_id、当前候选/job/版本、已做动作与回应时间；把关者请解释遗漏并提出可核查的不同条件。

`feedback.jsonl` 逐收件人记录 sent/delivery/ack/action，不能把工具投递成功写成 agent 已理解或改变行为。活跃者用 send_message；空闲者需要回复用 followup_task，但按槽位顺序执行。超出约定 ack 时限先查状态/重送，必要时中断相关新动作并保存，再恢复；不将沉默视为批准。共享文件更新、最终晨报都不能替代通知。

### 3. 运行处置限定到依赖 CH-01 的作业

执行者回执实际 run ID、实现/协议版本、已完成量、预计剩余成本、能否安全保存、当前运行是否能区分“机制无效”和“历史实现故障”。协调者按原授权处置：

- 当前运行依赖已被质疑前提且继续无新信息：安全保存/暂停，不再启动 A/B/C 变体；保留当前观测。
- 当前廉价完成可产出区分性证据：写成 `diagnostic-only`，明确成本与要检验的故障/预测，经协调者在已有预算内安排；不能将原批准悄悄继续当正式晋级。
- 无关作业继续。未提供当前成本/身份时先查证，不能直接凭候选名称杀作业；不越权取消、重启或扩大资源。

### 4. 把关者可以反驳，但无日志的故障猜测不能消除反证

把关者回应 `CH-01`：承认是否漏读 run-old，指出原放行哪条理由须修正，比较 A/B/C 是否改变失败条件。其“历史实现可能有故障”登记为竞争解释，不能写成已证实原因。

提案者回应最强反对，可提出具体可查故障、限定假设、撤回变体或提出不同预测；泛称值得试、调强度、换标题都不能解除 gate。验证者核查回应，读取历史代码/协议/日志和当前产物；若有效证据反驳自身判断，缩小或撤销 CH-01。若无新证据，停止语言争论，选择原预算内最小区分性动作，例如重算原始测量、检查必要干预是否实际发生、检查对照条件，或做小规模有效性诊断。具体动作由领域决定，不强塞 GPU/LLM 前向次数。

协调者决定资源分配，验证者判断证据问题是否解决；任何角色都不能靠地位、投票或轮数宣称科学事实成立。`diagnostic` 表示值得查，不表示假设已通过。

### 5. 证据更新后深化、放弃或搁置

- 若核实实现正确、协议可比、实验有辨别力且必要预测失败：放弃该条件下 A/B/C rev1 或机制族，撤销相关批准；不是永久否定研究主题。
- 若核实历史实现故障：故障证据绑定 run/version，修复核查后建立新候选/实现版本，再审；这是合法 reopen，不必虚构新科学机制。
- 若缺日志、辨别力或预算：保留 unresolved，以 park/diagnostic 处理；不能把疑点写成确定无效，也不能无限重跑来逃避历史。

向全部依赖方发送决策版本、旧结论撤销范围、新允许动作和 reopen 条件并收确认，依赖派发前复查。不是争议写进文件就算闭环。

### 6. D 独立评估，不被相同目标牵连

D 改变信息来源和可观测预测，目标部分相同不等于机制重复。提案者写明新信息如何改变原失败前提、与历史结果的关系、预测和反证；把关者独立比较。若 D 不依赖 CH-01 的被否定前提，在自身审核/授权成立时可推进；若仍共享某个必要前提，只限制该依赖，不因名称新而自动放行，也不因目标相同而全盘拒绝。

协调者在时间/预算内持续阅读、诊断、不同机制探索与实验。一个 A 失败、甚至整族放弃，不把 campaign 设 complete。截止/预算或真实无法继续的条件才按约定结束，并保存下一动作和在途状态。

### 7. 项目经验必须改变后续选择

记录 lesson：run/challenge 来源、实际观测、解释与不确定性、失败条件、可推翻证据、下轮检查和 reopen 条件。把关者下一次 gate-review 引用相关 lesson 并说明影响，验证者检查是否真的使用；合并机制族但保留原始证据。没有用户明确要求，不改个人记忆。

## 流程评价

| 风险 | 新版规则及本情境判定 |
|---|---|
| 门槛独裁 | 把关推荐接受独立质询；验证者也必须接受有效反驳；协调者管资源而不改事实。规则没有把任一角色设为不可挑战的科学权威。实际执行仍须保留未决证据，不能把“验证者决定是否解决”误用成无理由否决权。 |
| 过度否定 | 相似文献、一次故障、不可比旧结果不自动否定；允许 diagnostic 和条件性 reopen。D 可以继续；局部失败不生成永久禁令。 |
| 换名绕 gate | mechanism_signature、版本绑定、同族影响和复查条件能拦住 A/B/C 换名重提；强度变体可标 refinement，不能算三个新机制。 |
| 虚构并发 | 明确角色不等于常驻进程，四槽位要轮转。当前 P/E/R 并发时不能再启动 Gate，直到真实空出活跃槽。 |
| 反馈未传达 | 保存→真实工具投递→ack→action→复核→新版本再通知闭环完整；未确认阻断相关依赖派发。 |
| 一次失败就结束 | 明确要求在约定预算内继续其他动作；有限预算不等于无限自动扩容。 |
| 领域硬编码 | 基线、实验单位、变量、候选数量和门槛按本任务裁剪，非视觉/非 LLM 流程可用。 |

**当前结论：** 未发现阻断本情境的流程缺口；本演练能给出作者独立、证据可逆、反馈可追踪、有限并发和持续推进的安排。它仍是指令行为审查，不是实际消息工具回执、后台恢复或科研效果的实测。

## 新版 reproduction 的通用规则核查

重新读取后确认新版已经改变旧角色复用方式：协调者＋规划者＋执行者＋核查者可占四槽；计划核查者可以兼结果核查，但必须重新读原始证据、主动复查旧批准；规划者不再作为自己方案的唯一结果核查者。核查者亲自改对象须换另一独立人员，槽位不足顺序更换。

消息规则包含 finding_id、版本、证据、影响、临时决定、允许范围和回执；产物 pending review、阻断依赖、相关作业安全保存/暂停、无关作业继续，新版本重审再通知。任何角色可提异议，协调者组织证据争论而不能豁免作者不自审、证据真实或资源边界。

目标已推广到非训练实验，按实验单位/试次/场景采集证据，并允许不适用字段；实际配置/产物身份与审查版本绑定仍保留。没有发现必须有 GPU、checkpoint 或训练种子才能使用的要求。训练类例子仍较多，但被适用范围明确限定，不构成通用性阻断。
