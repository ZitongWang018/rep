# overnight-research-loop 独立行为审查

审查输入：skill 及四份 references；情景为两张卡运行至明早 8 点，已有全量 baseline，筛所有错题加 100 个正确题，达到 +3% 后测随机一半，不因一轮完成停止；过去 answer-position 视觉 message 放大没有稳定提高，继续视觉 CoT。此审查仅拟定行动，不启动 GPU、定时器或远程作业。

## 按此 skill 执行的第一轮

1. **建立本晚约定。** 用 Asia/Shanghai，实际启动当晚的次日 08:00 为截止，不把模板日期写死。资源总量为两张 GPU，而不是每个 agent 各两张。先从当前项目读取模型/benchmark 版本、代码、baseline 输出/评分器、两卡所在主机和旧失败记录；与 baseline 的精度、解码和 prompt 保持一致。缺失主机或评估入口会阻断实际运行，不阻断文献和假设整理。记录当前可用预算、额外前向上限及可恢复目录。
2. **遵守用户的筛选集合。** 本情景“baseline 已跑完全部题，筛全部错题”明确指全 benchmark。令 N 为总题数，E 为全部 baseline 错题、C 为全部正确题，固定种子从 C 无放回抽 100 个作为 C_s；不足 100 则使用全部正确题并记录。生成 S=E∪C_s 与哈希，每个候选都用同一 S。启动前固定随机半套 benchmark 的 ID；该半套将与筛选错题重叠，定位为扩展描述性评估，不宣称未接触的独立验证。不能把用户的“全部错题”静默缩为 search pool 的错题。
3. **落实 +3% 含义。** 优先从已有约定判断百分点/相对百分比；没有已有约定时说明本轮暂按净准确率提升 3 个百分点来筛选，请用户纠正，文献和可逆准备继续推进。筛选是错误富集集，不能将 S 上 +3 个百分点直接当作全 benchmark 提升。报告 repair、regression、两类比率；若 C_s 均匀抽样，使用 [repair−|C|·regression/|C_s|]/N 作为全池净增益估计及其不确定性，达到约定筛选信号后才扩大评估。100 个正确题的估计可能较宽，明确披露；阈值不等于统计显著性。
4. **读历史与主线文献后选择 top 2。** 文献 agent 深读与当前模型兼容的视觉证据整合/推理步骤研究，并将正文或代码位置接入候选记录。审查现场没有提供论文和模型实现，以下是待核实的候选方向，不能称为已被文献支持的机制。
   - **H1：视觉证据先行的可见 CoT。** 使用当前模型原有图像输入，在既有一次生成中先要求简短提取与问题有关的视觉事实再形成答案。假设失败源于推理没有使用现有视觉证据，而不是 answer-position message 强度不足。比较可见事实与答案的对应、纠错/退化、长度与延迟。限制额外 token，避免把更长 CoT 当作视觉增强本身的证据。
   - **H2：视觉证据在推理位置的整合。** 若当前架构可低成本干预，研究前段推理位置的视觉状态是否含答案位置未利用的互补信息，再考虑在原有前向内做信息转移。不是把旧 answer-position 放大挪个名字重跑。若仍只是同一方向的幅度放大、没有互补信息证据，验证者应要求修订。未知模型是否暴露所需 hook，因此这只是条件候选。
5. **独立验证门槛。** 验证 agent 阅读原旧实验、原代码和这两项候选，给 proceed/analyze-first/revise/reject。优先推进对输出影响潜力较大且无需重复昂贵前向的一个。H1 可做少量真实 evaluator 烟测；H2 先从固定小诊断子集保存决策有关的状态统计/预测变化，判断是否存在互补性。日志说明何种结果促使继续、改位置或放弃，不全量 dump hidden states。若 baseline margin 或微扰输出只在极少题轻微变化，则不无信息地扫大量强度。
6. **实施筛选。** 调度前读取 GPU 使用状态，明确 GPU ID/partition。两卡可各评估一个候选，或共同承担一个需要两卡的模型；根据模型占用和既有 evaluator 决定，不能默认为一候选一卡必然可行。每个 run 固定源码/config/ID/评分器，记逐样本输出、纠错/退化、可见证据、token、延迟、额外前向与 GPU-hours。已同协议的 baseline 复用；协议变化导致失配时，仅补必要的匹配 baseline。
7. **结果驱动下一轮。** 达门槛则冻结候选并测预先固定的一半，与同 ID baseline 配对比较，报告 n01/n10、净增益、配对区间和集合重叠。没达门槛先区分实现错误与假设失败，然后向文献 agent 返回观测，修订或换有根据的分支。一半未改善同样进入反思；一半改善后继续做授权范围内的稳定性/机制验证或下一候选，不因成功停止。每次看扩展结果登记为自适应验证，不能在持续选优后宣称独立最终性能。
8. **验证真实续接能力。** 查宿主是否存在可用持续会话、wakeup 或项目 controller；存在则按其实际接口配置并验证一次完成→归档→下一合法动作的事件链。没有就诚实说明只有当前活跃会话和已提交 detached 作业可以继续，不能保证聊天结束后还在产生新假设。监督周期先用 15 分钟并按运行长度调整；核查进程/作业、日志、checkpoint、metrics 和状态推进，通知仅针对有意义变化。到 08:00 不再派新计算，活跃作业按预先约定 checkpoint/完成/取消，输出晨报和可恢复状态。

## 关键歧义与影响

| 歧义/缺项 | 如何处理 |
|---|---|
| +3% 的单位与所指集合 | 从历史核实；暂定百分点并显式披露。错误富集集增益与估计全池增益分开，避免伪总体 +3% |
| 模型、benchmark、host 未给 | 优先从项目读取；无法推断则补必要输入。没有这些无法宣称运行已启动 |
| 额外前向/延迟上限 | 先核查既有预算；未给时先推进复用原有前向的机制，在升级成本前明确约定 |
| 全错题参与选择后的半套 | 服从用户集合；报告描述性扩展，不能包装成独立验证 |
| 08:00 的在途作业处理 | 启动时约定；预算截止不再派新作业，不能默认无限延长 |
| “以前试过”适用范围 | 查位置、模型、样本、强度、精度和负结果稳定性，避免过度否定视觉 CoT 主线 |

## Skill 的行为表现与建议

**判断：当前文本基本可用。** 能保留用户视觉 CoT 主线，要求负结果回流，按 top 2 灵活推进，且不会把一次实验完成误作任务完成。也明确没有实际 controller 就不能保证通宵自主推理。

- **值得保留的边界：** 对“全错题”的明确覆盖允许遵守用户情景；禁止一律换成留出搜索池。区分初始独立扩展、反复访问后的自适应验证，避免把测试选择偏差藏起来。无需新增 blanket test 禁止规则。
- **轻微一致性问题：** SKILL 主文写“达到预定筛选门槛后在预先冻结的半套 benchmark 上配对比较”，没有在这里提示“全错题选法的半套可能重叠”；reference 已纠正，实际读取后可以执行，但只读主文时可能遗漏。可加一句指向重叠与自适应验证的条件。
- **可执行歧义：** 默认 promotion_threshold 的字段没有直接指定该阈值作用于 S 准确率还是加权净增益估计。两者可能给完全不同的升级决定。建议补一个 promotion_metric 字段或要求 campaign 明记门槛所对应指标，使用用户明确选择，不硬锁唯一指标。
- **成本规则缺口：** 不要求默认 max_added_forward_passes 的固定数字合理，但真正启动前若字段仍为 null，应明确暂用零额外重跑原始完整 forward 的低成本路径，并记录 token 延迟预算；或者从现有资源估计形成可见暂定值。否则执行者可能在“卡数固定”的名义下做大量前向。
- **隐式长期资源授权风险受控：** skill 区分流程设计和实际执行，且当前情景明确给了两卡和时限；不把本次技能制作任务当作本晚运行授权。检查 agent 与后台作业是不同层，不会因四角色而四倍 GPU。
- **不需额外硬门槛：** 100 正确题带来不确定性，但无需禁止开展筛选；区间与退化可以指引是否增加正确样本，资源允许且用户同意或既有授权涵盖时做版本化调整。不必因为没有精确概率预测就否决候选。

本审查未复查实际项目证据、未做文献检索、未运行模型，也未验证宿主续接接口；以上是对 skill 在该情景下可观察的行为检查，不是机制有效或通宵部署成功的证据。
