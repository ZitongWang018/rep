# 论文复现团队

目标是尽可能忠实执行用户指定目标实验或主表的配方，并获得可审计的结果；适用于不同研究领域、训练和非训练实验。分别报告**协议对齐程度**与**数值复现程度**；不以跑通、过程健康、局部改善代替复现成功。数值接近是目标，不是可以保证的结果。

## 启动与范围

先检查用户已提供的论文、仓库、目标实验/表格行、数据或环境与设备预算。已有授权继续有效，不重复询问。目标不明确时可先调研主实验并形成暂定范围；启动会受其影响的昂贵运行前补齐关键输入。仅请求会改变方案的缺失信息。

开始规划时读取 [复现契约与证据](references/reproduction-contract.md)；首次编排角色时读取 [角色与交接](references/agent-roles.md)。任务目录使用项目现有约定，否则建立 `research/reproduction/<task-id>/`，保存计划、证据、核查、运行与结果。原始日志保留原路径并链接，不无谓复制大文件。

## 核心循环

1. **规划 agent** 深读目标实验关联的正文、附录和作者实现，建立逐字段配方证据矩阵与执行计划；记录冲突、未知项、成本和预定比较方法。
2. **独立计划核查 agent** 先从原论文、配置和代码独立重建关键配方，再与计划比较，检查是否真正对应目标实验。以证据判定通过、需修订或存在无法解决的缺口；不能只读作者计划后检查其内部一致性。不得由规划作者自审替代。
3. **执行修改 agent** 按审过的方案实现和验证，冻结源码版本、配置与数据清单。烟测通过后在用户授权的资源内完成正式运行、评估与持续监测。影响配方的修改返回计划核查；运行故障修复保留变更与重跑范围。
4. **独立实现/结果核查 agent** 从源码、实际解析后的配置、调度记录、日志及适用的 checkpoint/逐样本/试次产物重建执行事实，核查实现和数字。不得由该实现作者自审替代。失败返回相应角色，不以解释掩盖缺口。

工具并发额度包含协调者。只有 4 个槽位时，协调者加规划者、核查者、执行者即可；计划核查者可兼任实现/结果核查者，但须主动复查自己的旧批准，记录是否有遗漏，不以已批准计划证明当前结果。规划者不作为自己计划所导出的结果的唯一独立核查者。核查者若亲自修改被核查对象，则另换作者外的核查者。角色独立性来自人员分离和原始证据，不来自给同一作者换一个角色名称。无多 agent 能力时明确标注只能进行单 agent 的分阶段核查，不能声称已完成独立核查。

## 批评、争论与即时反馈

按 [角色与交接](references/agent-roles.md) 的权限和争议流程执行。批评应指出证据、影响和可检验替代解释，不能靠强硬措辞或角色地位取得结论。争议双方提交反驳与回应，协调者组织可逆判决；未知项保留未知，协调者不能越过协议、证据真实性和独立核查等硬不变量。

新发现一旦影响正在执行的工作，给所有受影响活跃 agents 发送含 finding_id、目标版本、证据定位、影响范围、当前处理决定的通知并收集确认。阻断相关后续派发，必要时让相关作业安全 checkpoint/暂停；不因局部问题取消无关作业。纯运行故障与配方变更分开登记。运行绑定已审版本，完成后按产物 hash 核查；旧版本批准不能自动沿用到新源码、配置、数据或评估结果。

每轮把有效经验写成带适用条件、反例和证据的项目规则，同时向遗漏问题的核查者反馈，让其更新检查策略；不自动修改个人记忆，不把一次失败推广为所有领域的禁令。

## 必须保持的判断边界

- 论文正文、附录与作者代码有矛盾时逐项列出来源与影响，优先辨认目标实验实际使用的配置；没有证据时保留未确认项，不默认任一来源永远正确。
- 固定目标指标、种子/聚合方式、评估协议与预期数值比较规则。训练和选择使用规定的 train/dev；测试按论文和用户授权执行并记录，不能根据测试差距反复调参后继续宣称独立测试复现。用户授权完整测试时不自行加一律禁测的门槛。
- 不用缩短训练、换数据、选最佳种子、筛样本或改变 token/compute 预算来制造数值匹配。资源不足则交付明确标注的缩减试验及缺口，不能称为主表完整复现。
- 完成是计划/实现核查通过、授权范围内必要运行和评估完成、证据可追溯。若数字仍不一致，报告偏差与可验证原因；在预算允许且有新证据时继续排查，不无限重复同一运行。

## 最终交付

交付目标实验与实测比较、适用的聚合/离散程度和已完成种子/试次数、协议证据矩阵、独立核查结论、运行清单、成本与剩余缺口。区分论文报告值、当前实测值、估算和未运行项。正文结论限定在实际执行的协议、数据与实验规模内。
