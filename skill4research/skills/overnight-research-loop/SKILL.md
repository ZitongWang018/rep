# 持续科研与批判反馈

目标：在约定时间和资源内，以文献、可检验假设、实验与相互质询持续推进研究。鼓励有意义的多元探索，保留和发展用户思想，同时允许充分证据推翻候选。一个实验结束不等于研究任务结束。

## 使用范围

区分设计流程、一次研究循环与实际持续执行。已有授权继续有效，读取项目资料补齐信息，不重复询问。具体领域、候选数量、评估样本、晋级阈值、设备和诊断变量由本次任务确定，不把过去项目设置作为默认范式。

执行前确定 [任务约定与状态](references/campaign-contract.md)。首次编排读取 [角色职责与权限](references/research-roles.md)；出现争议、同质化、重复尝试或负结果时执行 [质询、反馈与转向](references/feedback-and-diversity.md)。按用户请求和宿主能力编排子 agents，不增加平台并发配额。

## 科研循环

1. **历史与基线。** 从原始实验和决策重建尝试、成立/失败条件与未知项，建立机制级索引。核实评价协议，复用可比结果。
2. **文献与候选。** 提案 agent 深读相关工作，组织机制不同的方向；记录假设、可观测预测、实质区别和可能反证。数量由信息与预算决定，不固定名额、排名或并行宽度。
3. **idea 把关。** 把关 agent 独立对照历史与文献，审查候选间差异、推理链、影响潜力、可验证性和成本；对换名字/换强度的候选提出具体批评，不能只做格式检查或顺从提案。
4. **独立质询。** 验证反思 agent 检查候选及把关理由，提出最强反对、竞争解释和证据缺口。提案者回应，把关者重新判断，独立验证者核实回应；仅改变措辞不算解决。
5. **选择有信息价值的动作。** 依据证据选择实现、诊断、阅读、复算或低成本试验。写明哪些中间观测会改变判断。按 [通用评估协议](references/evaluation-protocol.md) 执行实验，采集有决策用途的变量。
6. **结果反馈。** 验证者读取原始结果，区分实现失败、假设不支持、协议问题与证据不足。负证据和同质化发现及时发给正在运行的相关 agents，尤其要求把关者解释为何放行并纠正判断；不能只留在晨报。
7. **深化或转向。** 有支持则验证稳定性、深化机制；充分反证则放弃该版本并通知依赖任务。陷入同机制变体时回到更本质的假设或探索不同机制，保留失败范围与重启条件。
8. **持续推进。** 协调者持久化状态、分配下一动作并监督真实运行。按 [运行协议](references/runtime-protocol.md) 续接；达到一个候选目标后在原约定内继续，不无限扩张预算。

## 权限与判断边界

- 相似文献不自动否定方向；与已失败本地实验实质重合须解释为何重试。未测量不能称明显无效。
- 把关者拥有候选推荐权并接受批评；验证反思者独立核查证据；协调者管理流程资源，不能把未解决反证改写为通过。不依赖争议的方向可继续。
- 相互说服依靠证据或区分性动作，不靠多数票、角色地位或争论次数。允许有信息价值的不确定探索，不要求实验前证明全部机制。
- 先保存并发送反馈，再依赖旧判断派发。被推翻批准失效；相关活跃任务按安全边界改向/暂停，保留产物，不误取消无关任务。
- 不同名称不是多样性；问题假设、机制、信息来源、目标、监督或评估解释的实质改变才可能产生不同方向，不追求形式名额。

## 记录与交付

维护 campaign、候选/实验/争议索引、项目内 lessons、反馈投递与确认、原始结果及恢复位置。记录可检查论证、证据、反对理由和决策变化，无需公开私有内部思维。经验注明适用范围与复查条件，不自动修改个人记忆。

按约定截止、预算、用户停止、新增授权需求或无法继续的实际条件结束。报告当前证据、已放弃和未决机制、把关判断修正、成本、在途任务及下一动作。技能文件不等于已部署后台运行器；研究结论限于真实证据。
