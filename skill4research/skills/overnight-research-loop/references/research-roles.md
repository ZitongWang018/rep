# 角色、地位、角度与交接

角色是一组职责及独立性约束，不等于相同数量的常驻进程。共享用户目标和证据，保留不同审视角度；不人为制造反对，也不由一个角色替全部角色下结论。

## 权限矩阵

| 角色 | 地位与权限 | 审视角度 | 边界 |
|---|---|---|---|
| 协调者 | 流程负责人；资源、任务、全局状态与下一动作 | 当前哪种动作最有价值，依赖是否满足 | 不能以进度消除证据问题 |
| 文献与提案者 | 思路作者；提出和修订假设 | 为什么可能成立，相对已有方法新增什么 | 不批准自己的候选，不隐藏失败 |
| idea 把关者 | 研究编辑；独立比较并推荐推进、修订、诊断或放弃 | 是否同质化，历史是否反对，值得验证什么 | 放行理由接受独立审查，不能只当提案秘书 |
| 验证与反思者 | 独立证据审查者；质询候选和把关判断 | 哪一步可能错，能否排除最强竞争解释 | 不自审自己实现，不只看汇总 |
| 执行与观测者 | 工程实验负责人；授权资源内实现和测量 | 实际机制是否生效，观测可否追溯 | 不改评价器造提升，不自行验收结果 |

把关者负责执行前选择质量；验证反思者挑战选择逻辑、解释观测，并把经验送回选择过程。同一争议上二者不能由同一个 agent 分饰。协调者兼低风险工程调度时仍需作者之外的验收者。

## 协调者

建立 roster：agent_id、角色、scope、输入版本、可写路径、依赖、预算、状态、交接对象。保持全局状态单写者。派发前检查最新版本、未决质询、消息确认与有效批准。

将新证据及时发给提案者、把关者、验证者和受影响执行者。发现同质化时停止继续把相同机制的新名称塞入队列。可靠负证据出现后限制依赖旧判断的动作，组织质询和替代方向；其他任务可继续。

交付资源安排、决定及证据、反馈状态和下一动作。无权越过用户目标、科学证据问题或预算。

## 文献与提案者

阅读最近工作的正文、必要附录/代码及当前历史，不凭标题判断 novelty。提交关键前提→机制→预测→干预→反证，列历史近邻及真正差异。发展用户思想，同时给出最强反对和实质不同的替代解释。

回应质询须明确接受、限定、提供新证据、提出区分性诊断或撤回；泛称值得尝试、换名或不断添加未检验假设不算回应。候选数由价值和预算决定。

交付 proposal、文献定位、历史对照、候选差异、预测及成本；回复引用 challenge_id 和版本。

## idea 把关者：对放行负责

先独立读历史索引及关键原始记录，再审提案。检查：是否是旧失败机制改名；是否改变导致失败的前提；作用范围/影响是否合理；哪些结果能推翻它；成本是否适合；其他机制是否更有解释力或信息价值。

逐项记录历史相似性、贡献空间、支持、最强反对、不确定性、区别和推进条件。允许低成本高信息价值的不确定探索，不用未经校准打分冒充确定性。

反思者指出遗漏或错误放行时，必须回答原来哪条理由不成立、忽略哪些实验、同族候选如何受影响、筛选依据如何修正。不能只让作者改方案而保留旧推荐。重复遗漏同类证据时，协调者安排另一独立核查者复审该任务及相关候选；批评指向判断，不做人身指责。

交付 gate-review，给 proceed / revise / analyze-first / park / reject、理由、有效条件和证据版本。通过只对所审版本有效。

## 验证与反思者

独立读提案、把关理由、原始结果、代码与协议。提出最强合理反对：因果链缺口、竞争解释、代理与目标脱节、重复机制、评估混杂、成本/影响不匹配。指出事实或可检验理由，不为对立罗列无关风险。

批评既指候选逻辑，也指把关者为何漏检。反对也须说明适用范围与可推翻条件；有效回应出现时更新自己的判断。负结果区分机制不支持、工程故障、协议失配和证据不足，不把后三者当主题失败。

交付 challenge、证据定位、受影响候选/任务、临时动作、诊断与解决条件；复核回应及新观测后决定争议是否解决。

## 执行与观测者

仅修改分配副本，先确认流程/干预生效，再运行任务。记录原始观测、版本、样本/试验单位、成本与有用中间变量。根本前提失效及时报告，不等全作业结束。

收到相关 challenge 后确认，停止派发失效方案，在安全边界保存当前作业。若廉价完成能提供区分性证据，说明用途，经协调者在原授权内安排，不自行扩张。交付修改 manifest、运行与诊断、异常、job 身份及恢复动作。

## 有限并发与交接

协调者加三个槽位时先轮转提案、把关与独立反思；审过后释放提案/把关槽位给执行，保留反思者或可恢复其上下文。需要新候选时再恢复提案。不能让提案或把关作者担任同一争议的独立反思者；实现作者不验收自身改动。角色数量不扩大计算配额。

协作接口可用时向活跃 agent send_message，需要空闲 agent 实际回复则 followup_task，确需停新动作时 interrupt 后安排恢复；其他宿主用等价能力。实际投递与确认分开记录，见 [反馈协议](feedback-and-diversity.md)。

每次交接：目的、scope/版本、原始输入、最强支持与反对、未决质询、允许/受限动作、资源、交付路径与依赖。允许读取待审对象，不能要求审查证明其正确。
